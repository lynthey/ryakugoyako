# 略語夜行

スマホ1台で遊ぶ略語当てパーティーゲームです。駅名標に出る略語を、正式名称に戻して声で答えます。

## 遊び方

1. `index.html` をブラウザで開きます。
2. 乗客（プレイヤー）の名前、出題ジャンル、テンポ（5段階）、ミスの上限、判定方式、サウンドを選びます。
3. 「出発進行！」で開始します。同じ人がミスの上限に達したら終点で、その人に罰ゲームです。

## リズムのルール

4拍子2小節（8拍）で1問です。拍は BGM の再生開始に合わせて数え、問題は必ず8拍の区切りから始まります。略語の読み上げは、各8拍の1拍目で始まります。

| 拍 | 内容 |
|---|---|
| 1〜4拍目 | 略語を読み上げます。マイクは常にオンですが、読み上げ中の音は判定に使わず、読み終わった瞬間から回答を受け付けます |

| 5〜6拍目 | 回答時間です |
| 7〜8拍目 | 締め切りです。8拍目が終わるまでに正解すると `ok1`（惜しい正解は `ok3`） |

延長はありません。拍がずれないよう、8拍目が終わった時点で時間切れです。何か答えていたら `ng1`、何も答えていなければ `ng2` を、BGMを止めてから鳴らします。

テンポは 90・100・110・120・130 BPM の5段階から選びます（初期値 120）。`bgm1.mp3` は元のテンポが 144 BPM なので、選んだテンポに合わせて再生速度を変えます（音程は変えません）。最初の拍の位置（約 0.025 秒）も、再生速度に合わせて補正します。

## 問題の読み上げ

設定の「問題の読み上げ」をオンにすると、端末に内蔵された音声合成で略語を読み上げます。読み上げが終わってから、制限時間と音声認識が始まります。

略語はすべてカタカナで出題します（短縮鉄道の夜の表記に合わせています）。英字を含む略語は `ケーワイ(KY)` のように括弧で添え、読み上げるのは括弧の前のカタカナだけです。駅名標では括弧の部分を小さく表示します。

カタカナにする前の表記（東大・KY など）は `const ORIG={...}` に残してあります。読み上げた略語が漢字や英字で認識されたときに、聞き取った文字から取り除くためです。

## 判定の順序

- 音声認識から返る候補（最大5つ）をすべて採点し、一番良い点を使います。候補の並び順には左右されません。
- 完全正解が1つでもあれば、その場で `ok1` にします。
- 「惜しい」だけの場合は、話している途中の暫定の文字の可能性があるので、すぐには確定しません。文が確定した時点か、0.4秒待っても完全正解に変わらなかった時点で `ok3` にします。
- 8拍目の終わりに「惜しい」が保留中なら、`ok3` として扱います。
- 「惜しい」は、聞き取った文字から略語そのもの（カタカナ・英字・もとの表記）を取り除いても惜しいときだけ認めます。正式名称が略語をほぼ含む問題（ワンチャン＝ワンチャンス など）で、略語を言い返しただけで正解にしないためです。

## 読み上げの声を拾わない工夫

マイクは常にオンのまま、ソフト側で読み上げの声を取り除いています。

1. 読み上げ中に届いた認識結果は、判定に使いません。
2. 読み上げの声と回答が1つの文につながって認識された場合は、読み上げ中に届いていた部分を先頭から取り除きます。
3. 聞き取った文字から、読み上げた略語（表記と読み方の両方）を取り除いてから、「何か答えたか」を判定します。聞き取り欄の表示からも取り除きます。
4. 読み上げ直後の0.35秒に届いた文字は、残響の可能性があるので「何か答えた」に数えません（正解の判定には使います）。

## 表記ゆれと英語での認識

- カタカナ語の表記ゆれは、比べる前にそろえます（フォ／ホ、ヴァ／バ、ティ／チ、ディ／ジ、小さい「ァィゥェォ」／大きい「アイウエオ」、長音「ー」の有無）。例：「スマートホン」「ワードプロセッサ」も正解になります。
- 音声認識がカタカナ語を英語で返すことがあります（例：「Word Processor」）。カタカナ語の問題には英語つづりの別解を登録しているので、英語で認識されても正解になります。辞書は `index.html` の `const EN={...}` です。
- 英語とカタカナが混ざって認識された場合（例：「Word プロセッサー」）は、英単語を1語ずつカタカナに置き換えてから比べます。辞書は `const EN_KANA={...}` です。
- 英語の別解は判定にだけ使い、端末内認識の「優先して聞き取る言葉」には渡しません（英語での認識を増やさないため）。
- オリジナル問題でも、`略語=正式名称|english spelling` のように「|」で英語の別解を書けます。

## 端末内の音声認識

Chrome 139 以降では、音声認識を端末内で行えます。設定の「音声認識の場所」を「端末内（精度重視）」にすると、次のように動きます。

- 通信なしで認識するので、サーバー側の遅れや停止の影響を受けません。
- 出題中の正解と別解を「優先して聞き取る言葉」として認識エンジンに渡します。
- 日本語データが入っていない場合は、設定画面の「日本語データを入れる」で一度だけダウンロードします。
- 端末内認識が使えない環境やエラーが出たときは、自動でクラウド（Google のサーバー）での認識に戻ります。

聞き取り欄の状態表示に「（端末内）」「（クラウド）」のどちらで動いているかが出ます。

## 診断表示（音声判定のとき）

プレイ画面の聞き取り欄に、次の3つを表示します。音声が入らないときの原因を切り分けるためのものです。

- MIC バー：マイクに入っている音の大きさです。声を出しても動かなければ、マイク自体に音が届いていません。
- 認識の状態：「動作中」「マイク受信中」「声を検出」「停止→再開（n回目）」「エラー：…」を表示します。
- 受付状態：「受付中」のときだけ、聞こえた内容を判定に使います。「読み上げ中（無視）」「待機」のときは判定しません。

音声認識が止まったままになる対策として、次の2つを入れています。

- 判定のたびに、音声認識を作り直します。立ち上がりの時間は、次の問題が始まるまでの間に収まります。
- 受付中に MIC バーが0.7秒以上反応しているのに認識が何も返さないときは、その場で認識を作り直します（「認識が反応しないため再起動」と表示）。この見張りは MIC バーを表示しているときだけ働きます。

MIC バーは、設定の「マイク入力バー（診断用）」で消せます。端末によっては、バー用のマイク取得と音声認識が同時にマイクを使うと、認識の調子が悪くなることがあります。その場合はバーを消してください。

## 音声判定を使うには

音声認識はマイクを使うため、https で配信されたページでしか動きません。

- GitHub Pages などの https サイトにこのフォルダを置き、Android の Chrome か iPhone の Safari で開きます。
- `file://` で直接開いた場合や、非対応のブラウザでは、自動で手動判定になります。

## サウンド

設定画面の「サウンド」で次の3つから選びます。

- sound フォルダの音源：`sound/` に置いた mp3 を使います。
  - `s1.mp3`：開始時のジングル。終わると続けて `bgm1.mp3` をループ再生します。
  - `ok1.mp3`：8拍目までに正解。`ok3.mp3`：8拍目までに惜しい正解（ほぼ一致）。`ok2.mp3` は現在使っていません。
  - `ng1.mp3`：何か答えたが正解しないまま時間切れ、または手動の×。
  - `ng2.mp3`：何も答えないまま時間切れ。
  - 時間切れのときは、BGMを止めてから鳴らします。
  - ミスのあとは「仕切り直して発車」で、鳴っている `ng1`・`ng2` を止めてから `s1.mp3` のジングルで再スタートします。
  - 見つからないファイルは、オリジナル音源で代わりに鳴らします。
- オリジナル音源：ゲーム内で生成する発車チャイムとBGMを使います。
- 効果音だけ：BGMなしで、オリジナルの効果音だけを鳴らします。

`sound/` フォルダは `.gitignore` で除外しています。権利を持たない音源を公開リポジトリに含めないでください。音源が無い環境（GitHub Pages など）では、自動でオリジナル音源になります。

## 出題ジャンル（路線）

日常・仕事／食べ物・お店／エンタメ／組織・乗り物／ネット・若者言葉／実は略語／オリジナル の7路線です。

- 「実は略語」は、教科書（教科用図書）や電卓（電子式卓上計算機）のように、略語だと気づきにくい言葉です。
- 「ネット・若者言葉」には、中高生がよく使う言葉（とりま、イツメン、ビジュ、エゴサなど）も入れています。流行り廃りが速いので、古くなったものは適宜入れ替えてください。

## マイクテスト

最初の画面の「オプション」にある「マイクテスト」で、ゲームを始める前にマイクと音声認識を確かめられます。入力の大きさのバーと、認識した文字がその場で表示されます。20秒たつか、もう一度押すと止まります。

- 5秒たってもマイクを開けないときは「Chrome を完全に終了して起動し直してください」と表示します（Chrome の音声処理が固まったときの症状です）。
- 端末内認識が起動直後に3回続けて止まったら、ゲーム本番と同じくクラウドの認識に切り替えます。

## 出題の順番

ゴロの似た略語（〜コン、〜イチ、〜ハラ、アラ〜 など）は、2〜4問ずつ固めて続けて出します。グループは `index.html` の `const GORO={...}` に、語尾（`end`）と語頭（`head`・`first`）で並べてあります。1つの略語は当てはまるすべてのグループに入り、どのグループの塊で出るかは毎回ランダムです。

塊は「揃い」を続けたあと、最後に「外し」を1問入れます（例：シュウイチ→ツキイチ→パンイチ、アルハラ→セクハラ→ウラハラ）。似た派生が続いたところで、音は同じでも意味が全く違う語が来るのが狙いです。「揃い」は、グループの正解のうち一番多くの語が共有している部分（〜イチなら「1回」、〜ハラなら「ハラスメント」）で自動的に見分けます。共有部分が見つからないときは、ジャンルが同じものを「揃い」にします。

## 難しい問題の表示

問題ごとの出題数と間違えた回数を、その端末の `localStorage`（`ryakugo-stats`）に貯めます。間違いが `HARD_MISS`（3回）以上になった問題は、駅名標に「難しいよ！」と出します。記録は端末ごとで、外部には送りません。

## 問題の追加

設定画面の「オリジナル問題」に、1行1問で `略語=正式名称` と書きます。別の言い方も正解にしたいときは `|` で区切ります。

組み込みの問題は `index.html` の中の `const Q=[...]` にあります。形式は `["略語","正式名称|別解","ジャンル記号"]` です。

判定は文字の一致で行い、漢字の読みは比べません。そのため、漢字を含む答えには、ひらがなの読みや、認識されそうな別の表記（例：安全牌｜安全パイ｜あんぜんぱい）を別解として並べておきます。カタカナとひらがな、長音、空白、中黒の違いは判定側でそろえるので、どちらか一方を書けば足ります。

「短縮鉄道の夜」の出題キーワード（2007〜08年の放送記録）から選別した語も入れてあります。重複・誤記・略語でないもの・答えが不確かなものは除き、誤記は直してから入れています。
